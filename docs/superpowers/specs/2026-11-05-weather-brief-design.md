# 丰富数据、简洁回答

用户已确认：天气查询默认获取较完整的数据，但回答保持一到两段纯文本，不加图标、表情或逐项罗列。优先实际温度、体感、全天高低温、风雨变化和可执行建议；湿度、空气质量只在有意义时提及，重要预警优先。

## 方案与边界

采用完整数据包加简洁回答引导。只增强原有字段不足以支持生活指数；每次逐项展示所有字段已被用户否决。

保留 `get_weather(location, when, focus)` 和三个配置参数，保留 AstrBot 当前 LLM 生成最终回复，不发送额外消息。新增简报补充层，复用已缓存的 current/daily/hourly，按目标日期匹配生活指数，今日才附加实时空气质量和有效预警。不把今日指数或当前实况套用到未来。

基础天气保留现有结果；补充数据独立返回 brief，标记可用性和覆盖时间。小时汇总覆盖整个相关时段，最大逐小时降雨概率不冒充整个时段的降雨概率。缺失降雨量保持 null，不变成零。附加请求并发、有界超时、缓存和并发去重；失败只留下稳定警告码，不泄露 URL 或密钥。

生活指数使用 QWeather v7 indices（1 运动、2 洗车、3 穿衣、5 紫外线）；当前空气质量使用 airquality v1，预警使用 v7 warning。授权、覆盖范围由用户账号决定，没有数据不生成指数或“无预警”结论。

## 回答契约

默认一到两段自然纯文本，不加图标或表情，不使用标题、表格或编号清单。第一段说明天气、气温/体感、全天范围和穿衣；第二段说明显著风雨变化和相关生活建议。不要强行填满所有字段或输出空缺清单。仅用真实可用数据；用户要求简单或详细时尊重本轮要求。输出长度是给宿主 LLM 的引导，不能保证所有模型完全遵循。

## 验证

通过真实服务编排与 MockTransport 验证请求协议、日期匹配、晚些时候降雨、缺失值、权限失败、缓存/并发、无未来实况混用。运行全量 Python 和现有 JavaScript 测试。当前无真实 API 凭据，真实账号联调和最终 LLM 文字效果不宣称已验证。

本设计是对旧 SPEC v1.3 中不接生活指数/空气质量的明确扩展，其余架构约束保持。
